This page is generated from the same Go configuration structs used by the server. Every leaf setting can be supplied as a config-file key, a `TELDRIVE_` environment variable, or a CLI flag on `teldrive run` and `teldrive check`.

The precedence order is **defaults < config file < environment variables < explicitly supplied CLI flags**. Only flags you actually pass override lower-precedence sources.

The config file can be selected explicitly with `--config PATH` / `-c PATH`. Without it, Teldrive searches `$HOME/.teldrive/config.toml`, `.yaml`, `.yml`, then the same filenames in the current directory.

## How the names map

The mapping is mechanical. For example, all three of these set the same value:

```yaml
http:
  address: 0.0.0.0:8080
```

```bash
TELDRIVE_HTTP_ADDRESS=0.0.0.0:8080
```

```bash
teldrive run --http-address 0.0.0.0:8080
```

Nested config dots become hyphens in CLI flags and underscores in environment variables. Slice values supplied through environment variables or flags are comma-separated. Durations use values such as `10s`, `5m`, or `1h`; size values accept forms such as `5MB`. Encryption key maps use comma-separated `version:key` entries.

Run `teldrive run --help` or `teldrive check --help` to inspect the flags supported by the exact binary you are running.

The **Default** column is the literal runtime default from the code, not a production recommendation. Follow the focused configuration guides for security-sensitive choices. Teldrive ships with public Telegram application credentials, so most installations do not need to override `telegram.app-id` or `telegram.app-hash`.
