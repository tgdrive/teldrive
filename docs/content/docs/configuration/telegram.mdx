---
title: Telegram settings
description: Configure Telegram connectivity, concurrency, channels, proxies, and download clients.
---

Teldrive includes public Telegram application credentials. For your own credentials, follow [Custom Telegram application](/getting-started/telegram-application).

## Connection

```yaml
telegram:
  backend: remote
  dial-timeout: 10s
  reconnect-timeout: 5m
  max-retries: 10
  rate-limit: true
  rate-interval: 50ms
  rate-burst: 10
```

Keep rate limiting enabled unless you have a specific reason to change it. The limit applies to each Telegram account separately: your user account and every bot each get their own `rate-interval`/`rate-burst` budget, so adding bots adds request capacity.

## Uploads

```yaml
telegram:
  upload-threads: 8
```

Valid range: `1`–`32`. Increase only after measuring throughput and Telegram errors.

## Downloads

```yaml
telegram:
  download-bots: 0
  download-client-pool: false
  download-read-buffers: 32
  download-read-parallel: 4
```

- `download-bots`: `0` uses the authenticated user; up to `32` enables the first N enabled bots (by bot ID) for downloads.
- `download-client-pool`: keeps one authenticated download client warm per download bot (or the user account) when enabled. Each download still goes to the least-loaded bot; idle warm clients do not count as load.
- `download-read-buffers`: prefetched chunks per stream, range `1`–`256`.
- `download-read-parallel`: concurrent chunk fetches per stream, range `1`–`32`.

Increasing buffering/parallelism raises memory and Telegram request pressure across simultaneous downloads.

## Storage channels

```yaml
telegram:
  randomize-part-names: true
  auto-channel-create: true
  channel-part-limit: 500000
  channel-name-prefix: teldrive
```

See [Storage channels](/using/channels).

## Bot rotation

```yaml
telegram:
  bot-rotation-backend: memory
```

Each upload or download goes to the eligible bot with the fewest Telegram connections in use on this instance, so a busy bot is skipped while an idle one is available. When several bots are equally loaded, the rotation backend decides which goes next. Use `memory` for one instance and `database` when multiple instances must coordinate that rotation. Load is tracked per instance.

## Proxy

Standard HTTP/HTTPS/SOCKS5 proxy:

```yaml
telegram:
  proxy: "socks5://user:password@proxy.example.com:1080"
```

MTProxy:

```yaml
telegram:
  mtproxy:
    address: "proxy.example.com:443"
    secret: "YOUR_SECRET"
```

Do not configure both. MTProxy address and secret must be set together.

## Client logging

```yaml
telegram:
  client-logging: false
```

Enable temporarily for low-level Telegram diagnostics.

## Filesystem backend

For development/tests only:

```yaml
telegram:
  backend: filesystem
  local-root: ./var/local-telegram
```

This stores payloads locally instead of in Telegram.
