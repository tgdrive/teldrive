Teldrive exposes a versioned HTTP API used by the web UI, rclone, and other external clients. The contract is authored in **TypeSpec** and generated into `openapi/teldrive.openapi.yaml`.

## Base URL

For a server at:

```text
https://drive.example.com
```

most application endpoints live under:

```text
https://drive.example.com/v1/...
```

Health checks are intentionally outside `/v1` under `/health/...`.

## Main resource groups

The API includes:

| Area | Prefix / purpose |
| --- | --- |
| Authentication | `/v1/auth`, `/v1/me`, sessions |
| API keys | `/v1/api-keys` |
| Files/folders | `/v1/files`, `/v1/folders` |
| Uploads | `/v1/uploads` |
| Shares/grants | `/v1/files/{id}/shares`, `/v1/shares`, `/v1/public/shares` |
| Channels | `/v1/channels` |
| Bots | `/v1/bots` |
| Jobs | `/v1/jobs` |
| Periodic jobs | `/v1/periodic-jobs` |
| Storage statistics | `/v1/storage` |
| Events | `/v1/events` |
| System health | `/health/live`, `/health/ready` |

Use the [interactive API reference](/api/reference) for the exact request/response schema of the current source tree.

## Authentication choices

Authenticated endpoints accept one of the supported Teldrive authentication mechanisms:

- browser cookie (`teldrive_access`);
- bearer token (`Authorization: Bearer ...`);
- external API key (`X-Api-Key: ...`).

For automation and rclone, prefer a dedicated API key rather than copying browser cookies.

See [Authentication](/api/authentication) and [API keys](/api/api-keys).

## Idempotency

Operations that can safely be retried expose the `Idempotency-Key` header. Generate a stable UUID for one logical operation and reuse that UUID only when retrying the same request.

Example:

```bash
curl -X POST https://drive.example.com/v1/folders \
  -H 'X-Api-Key: YOUR_KEY' \
  -H 'Idempotency-Key: 5a583949-311c-4d29-a395-09d908646e58' \
  -H 'Content-Type: application/json' \
  --data '{"name":"Photos"}'
```

Do not reuse one idempotency UUID for unrelated operations.

## Optimistic concurrency

Some updates use an `If-Match` precondition with an ETag. This prevents one client from silently overwriting another client's newer change.

If the resource changed after you read it, refresh the resource and retry with the new ETag instead of disabling the precondition.

## Pagination

List APIs commonly use cursor pagination with:

```text
?limit=100&cursor=...
```

The server returns a `nextCursor` when another page is available. Do not manufacture or parse cursors; pass the returned value back verbatim.

## Errors

Application errors use a stable envelope:

```json
{
  "error": {
    "code": "machine_readable_code",
    "message": "Human-readable explanation",
    "details": {}
  }
}
```

Automation should branch on the stable error code/status rather than parsing the English message text.

## Source of truth

Do not hand-maintain clients from screenshots or guessed payloads. The authoritative contract is:

```text
typespec/*.tsp
    ↓ generated
openapi/teldrive.openapi.yaml
```

The API reference in these docs is rendered from that generated OpenAPI document.
