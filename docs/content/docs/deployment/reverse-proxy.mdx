---
title: Reverse proxy and HTTPS
description: Put Teldrive behind a TLS reverse proxy without breaking cookies, uploads, or SSE.
---

Keep Teldrive private and terminate TLS at the proxy:

```text
browser ──HTTPS──► proxy ──HTTP/private network──► Teldrive :8080
```

## Trusted proxies

Trust only the address/CIDR of the proxy that connects directly to Teldrive:

```yaml
http:
  trusted-proxies:
    - 127.0.0.1
```

Teldrive accepts `X-Forwarded-Proto: https` only from trusted peers. Do not use `0.0.0.0/0` or `::/0`.

Request logs report the client from `X-Forwarded-For` when the direct peer is trusted. Teldrive reads the header right-to-left, skipping trusted hops, so clients cannot spoof their address by prepending entries. Requests from untrusted peers log the peer address.

## Caddy

Same host:

```text
drive.example.com {
    reverse_proxy 127.0.0.1:8080
}
```

```yaml
http:
  address: 127.0.0.1:8080
  trusted-proxies:
    - 127.0.0.1
```

For containerized Caddy, trust the actual container-network source CIDR instead.

### Optional: `tgdrive/caddy` with varc

The [`tgdrive/caddy` image](https://github.com/tgdrive/docker-images/tree/main/caddy) includes [varc](https://github.com/tgdrive/varc), a sparse byte-range cache for large downloads and media seeking. Standard Caddy remains sufficient for HTTPS; caching is optional.

Add Caddy to the same private Compose network as Teldrive:

```yaml
services:
  caddy:
    image: ghcr.io/tgdrive/caddy
    ports:
      - "80:80"
      - "443:443"
    volumes:
      - ./Caddyfile:/etc/caddy/Caddyfile:ro
      - caddy_data:/data
      - caddy_config:/config
      - varc_cache:/var/cache/varc
volumes:
  caddy_data:
  caddy_config:
  varc_cache:
```

Save this as `Caddyfile`, replacing the domain:

```text
drive.example.com {
    @stream {
        method GET HEAD
        path_regexp stream ^/api/v1/files/([0-9a-fA-F]{8}(?:-[0-9a-fA-F]{4}){3}-[0-9a-fA-F]{12})/content(?:/[^/]+)?$
        not query download=1
    }

    handle @stream {
        varc http://teldrive:8080{http.request.uri} {
            cache_dir /var/cache/varc
            key "{re.stream.1}"
            max_size 100GiB
            min_free_space 5GiB
            max_age 24h
            poll_interval 1m
            chunk_size 64MiB
            chunk_size_limit 1GiB
            chunk_streams 4
            read_ahead 256MiB
            buffer_size 32MiB
        }
    }

    handle {
        reverse_proxy teldrive:8080
    }
}
```

Set Teldrive's listener to `0.0.0.0:8080` inside its container and trust only the private network used by Caddy. Do not publish Teldrive's port publicly.

This caches GET/HEAD streaming requests to `/api/v1/files/{fileId}/content/{fileName}` and the legacy `/api/v1/files/{fileId}/content` URL. Requests with `download=1` bypass varc and use ordinary reverse proxying, as do all other routes—including login, uploads, shares, and live events. The dynamic upstream preserves query parameters. The regular expression captures the file ID as `{re.stream.1}`, so both URL forms (regardless of filename) use the same cache entry per file. Cache entries are shared across credentials; do not key on `Authorization` or `Cookie`, which would duplicate cached files for each token or cookie. Do not replace incoming credentials with a shared service token.

With default authentication enabled, Varc opens the origin object before serving anything—even on a cache hit—and forwards the caller's own cookies/authorization with a metadata request to Teldrive. Rejected credentials cannot retrieve cached bytes. Test unauthenticated access and revoked credentials after warming the cache. Origin authentication errors may appear as cache-proxy errors rather than their original HTTP status.

For direct playback in VLC, MPV, or similar players without credentials, administrators can explicitly set `security.public-file-content: true` (or `TELDRIVE_SECURITY_PUBLIC_FILE_CONTENT=true`). This disables authentication **only** for GET/HEAD file content requests (both legacy and filename URLs, including `?download=1`), not for listing or other APIs. **Warning:** anyone with a file ID can retrieve any active file on this instance, regardless of its owner or sharing settings; Varc's origin authorization check cannot protect these public files. Leave this option disabled unless you intend to expose all active file content.

Adjust the disk limits to your host and keep this volume private. Use one cache directory per Caddy process. See [varc options](https://github.com/tgdrive/varc#caddy-module) for tuning.

Validate and start:

```bash
docker compose run --rm caddy caddy validate --config /etc/caddy/Caddyfile --adapter caddyfile
docker compose up -d caddy
docker compose logs --tail=100 caddy
```

This configuration requires a varc build with dynamic-upstream support. It is not covered by Teldrive's end-to-end tests. Validate the Caddyfile with the image you deploy, then test downloads, seeking, and authentication failures before enabling the cache for users.

## nginx

```nginx
server {
    listen 443 ssl;
    server_name drive.example.com;

    ssl_certificate     /etc/letsencrypt/live/drive.example.com/fullchain.pem;
    ssl_certificate_key /etc/letsencrypt/live/drive.example.com/privkey.pem;

    client_max_body_size 0;

    location / {
        proxy_pass http://127.0.0.1:8080;
        proxy_http_version 1.1;
        proxy_set_header Host $host;
        proxy_set_header X-Forwarded-Proto $scheme;
        proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
        proxy_request_buffering off;
        proxy_buffering off;
        proxy_read_timeout 3600s;
        proxy_send_timeout 3600s;
    }
}
```

Adjust timeouts for your deployment; file transfers and SSE require long-lived requests.

## Container binding

```yaml
services:
  teldrive:
    ports:
      - "127.0.0.1:8080:8080"
    environment:
      TELDRIVE_HTTP_ADDRESS: 0.0.0.0:8080
      TELDRIVE_HTTP_TRUSTED_PROXIES: 172.18.0.0/16
```

Replace the example CIDR with the network your proxy actually uses.

## Verify

After enabling HTTPS, test:

- login and page refresh;
- upload/download;
- live task/progress updates;
- no repeated SSE reconnects or cookie errors.

If a CDN/load balancer sits in front of your proxy, Teldrive should still trust only its direct proxy peer; that proxy must sanitize forwarding headers.
